# Platform API (SPEC 09 and 10)

NestJS backend on Fastify with TypeORM and Postgres (database `plataforma`). Since SPEC 09 it serves authentication (it replaced the previous workflow-based auth service and its reverse proxy); since the SPEC 10 cut-over it serves the whole school (roles, categories, courses, syllabus, public catalog, review, support team, covers and videos). It is the only entry point of the stack (`127.0.0.1:3000`).

**Rule (SPEC 09, applied by SPEC 10): GraphQL for the domain, REST for the edges.**

| | Goes in | Why |
|---|---|---|
| Reads and mutations of the domain: roles, categories, courses, syllabus, catalog, review, team, video state, confirm cover/video, retry and delete video | **GraphQL** (`POST /api/graphql`) | One protected endpoint, persisted queries, role guard, cost limit |
| Authentication (`/api/v1/usuarios`, `/sesiones`, `/verificaciones-correo`, `/recuperaciones`) | **REST** | The `HttpOnly` refresh cookie |
| Upload signatures to Storage (`/api/v1/portadas/firmas`, `/api/v1/videos/firmas`) | **REST** | They hand out a URL, they are not queries |
| Internal webhook (`/api/v1/interno/video-procesado`), health, email templates | **REST** | Called by machines, not by the browser |

The code is in English and organised by NestJS modules. The **contract stays in Spanish**: REST routes, JSON and GraphQL fields, error codes and messages, tables and columns, and `.env` variables.

## Architecture

```text
browser -> Astro proxy (/api, /almacen) -> api :3000 (NestJS + Fastify)
                                             |- REST    /api/v1/*      -> Supabase Auth (auth:9999), Storage (storage:5000) and Postgres plataforma
                                             |- GraphQL /api/graphql   -> local JWT check, roles from the database, Postgres plataforma
                                             |- /plantillas-correo/*   -> static email templates for Supabase Auth
                                             '- webhook /api/v1/interno/video-procesado <- transcodificador:8090 (internal network)
transcodificador:8090 <- the API asks for jobs (POST /trabajos, X-Secreto-Transcodificador)
```

```text
src/
  main.ts, app.module.ts
  config/            configuration.ts (reads and validates the environment at startup, never prints values), config.module.ts
  common/            filters/, guards/, pipes/, decorators/, utils/, services/, validators/, scalars/ (EnteroGrande), models/
  database/          database-options.ts, run-migrations.ts, migrations/
  modules/           (see the table below)
graphql/             schema.graphql (generated, versioned), persisted-queries.json (generated by the frontend codegen)
templates/           verificacion.html, recuperacion.html, cambio_contrasena.html, team-invitation.html
data/                common-passwords.txt (SecLists, source commit in the header)
scripts/             create-admin.sh, create-covers-bucket.sh, create-videos-bucket.sh, create-platform-database.sh,
                     generate-school-postman.py
test/                e2e specs and helpers/
postman/             two collections (auth, school) and the local environment
```

Each module has its own entities (TypeORM, `schema: 'escuela'`, Spanish `snake_case` columns), repositories, services, DTOs (`class-validator`), resolvers or controllers and guards. `Course.busqueda` is read-only (generated column); `VideoKey.clave` is `select: false` and never leaves the API.

- **Cross-cutting layer** (what Caddy used to do), in `src/common/`: CORS only for `ORIGEN_FRONT` with credentials; security headers (`nosniff`, `no-store`, `no-referrer`, CSP `default-src 'none'`, no `Server` or `X-Powered-By`); `405` with `Allow`, `415`, `413` above 10 KB, `400 JSON_INVALIDO`, `404 NO_ENCONTRADO` and `500 ERROR_INTERNO` without details, all with the uniform error format; real client IP (`X-Forwarded-For` is only trusted when the direct peer is in `PROXIES_CONFIANZA`); `X-Solicitado-Con: front` required on renewal.
- **Validation:** `class-validator` with DTOs (global `AppValidationPipe`, whitelist, no extra fields). The register and login bodies go through `modules/auth/validators/request.validators.ts` (pure functions) so the messages and the order of `detalles` stay byte-for-byte what the front already consumes. Zod lives only in the frontend.
- **Users and sessions** stay in Supabase Auth (`auth.users`, `auth.sessions`); the API calls `/signup`, `/token`, `/verify`, `/recover`, `/resend`, `/logout`, `/user` and the admin endpoints on `URL_SUPABASE_AUTH` (default `http://auth:9999`, timeout `TIEMPO_ESPERA_AUTH_MS` = 8000). Any network failure or unreadable response gives `500 ERROR_INTERNO` without details.

## Run

The container (`api` in `docker-compose.yml`) runs `NODE_ENV=production` with a non-root user, read-only filesystem, `cap_drop: [ALL]` and `no-new-privileges`, and publishes only `127.0.0.1:3000`. It reaches `auth:9999`, `db:5432`, `storage:5000`, `transcodificador:8090` and `mailpit:1025` through the internal network. It depends only on `db`.

```bash
api/scripts/create-platform-database.sh   # once, if the Postgres volume already existed
docker compose up -d --build api          # runs the migrations, then serves on 127.0.0.1:3000
curl 127.0.0.1:3000/api/v1/salud          # {"listo":true}
```

For development on the host (GraphQL in development mode: full queries, introspection and GraphiQL):

```bash
cd api && npm install
npm run start:dev                         # reads the same environment variables; the database is not published, so point BD_HOST to a reachable Postgres
```

The Postgres container is not published on the host. Without a reachable database, develop against the container: `docker compose up -d --build api`.

## REST contract (`/api/v1`)

Everything is JSON (`Content-Type: application/json`), identifiers in `snake_case` and Spanish. The base URL is `http://127.0.0.1:3000`. Origin: any `Origin` other than `ORIGEN_FRONT` gets `403 ORIGEN_NO_PERMITIDO`.

| Method and route | Input | Success |
|---|---|---|
| `POST /api/v1/usuarios` | `{ nombre, correo, contrasena }` | `201 { mensaje }`, identical for a new or an already registered email |
| `POST /api/v1/sesiones` | `{ correo, contrasena }` | `200 SessionResponse` + cookie |
| `POST /api/v1/sesiones/renovacion` | cookie + `X-Solicitado-Con: front` | `200 SessionResponse` + rotated cookie |
| `DELETE /api/v1/sesiones/actual` | `Authorization: Bearer <token_acceso>` | `204` and the cookie is cleared |
| `POST /api/v1/verificaciones-correo` | `{ correo, codigo }` | `200 { mensaje }` |
| `POST /api/v1/verificaciones-correo/reenvio` | `{ correo }` | `202 { mensaje }` |
| `POST /api/v1/recuperaciones` | `{ correo }` | `202 { mensaje }` |
| `POST /api/v1/recuperaciones/restablecimiento` | `{ correo, codigo, contrasena_nueva }` | `200 { mensaje }` |
| `GET /api/v1/salud` | none | `200 { "listo": true }` |
| `POST /api/v1/portadas/firmas` | `{ curso_id, tipo_contenido, tamano_bytes }` + Bearer | `201 { url_subida, ruta }` (see Edges of the school) |
| `POST /api/v1/videos/firmas` | `{ clase_id, nombre_archivo, tipo_contenido, tamano_bytes }` + Bearer | `201 { video_id, url_subida, ruta }` |
| `POST /api/v1/interno/video-procesado` | `{ video_id, resultado, duracion_segundos?, mensaje? }` + `X-Secreto-Transcodificador` | `200 { aplicado }` |

`SessionResponse`:

```json
{ "token_acceso": "<JWT>", "tipo_token": "Bearer", "expira_en": 900,
  "usuario": { "id": "...", "correo": "ana@example.com", "nombre": "Ana" } }
```

`token_acceso` is an HS256 JWT valid for 15 minutes. It goes in `Authorization: Bearer ...` and the frontend keeps it only in memory.

**Refresh cookie** `token_renovacion`: `HttpOnly; SameSite=Strict; Path=/api/v1/sesiones; Max-Age=604800` (7 days), no `Secure` (no TLS yet). It never travels in a body. Requests that carry it must be sent with credentials (`withCredentials: true`).

### Register: `POST /api/v1/usuarios`

```http
POST /api/v1/usuarios
Content-Type: application/json

{ "nombre": "Ana", "correo": "ana@example.com", "contrasena": "Zorro#Azul-2026x" }
```

```json
201  { "mensaje": "Cuenta creada. Revisa tu correo y verifícala con el código que te enviamos." }
```

- `correo`: valid, up to 254 characters (stored in lower case). `nombre`: 1 to 80 characters, no control characters. No extra fields.
- Anti enumeration: same code, body and (floor of 600 ms) time whether the email exists or not. Registration does not open a session.
- The account is unverified: a 6-digit code arrives by email. Until then login gives `403 CORREO_NO_VERIFICADO`.
- Password policy (all failing rules are returned together in `detalles`): `minimo_12_caracteres`, `maximo_72_bytes`, `requiere_mayuscula`, `requiere_minuscula`, `requiere_numero`, `requiere_simbolo`, `sin_espacios_extremos`, `no_contiene_correo`, `no_es_comun` (not among the 10 001 common passwords, also tested without trailing digits and symbols) -> `422 CONTRASENA_INSEGURA`.

### Login: `POST /api/v1/sesiones`

- `200 SessionResponse` + `Set-Cookie: token_renovacion=...; HttpOnly; SameSite=Strict; Path=/api/v1/sesiones; Max-Age=604800`.
- `401 CREDENCIALES_INVALIDAS`: unknown email and wrong password give exactly the same response.
- `403 CORREO_NO_VERIFICADO`: correct password on an unverified account (does not count as a failed attempt).
- Lockouts in a 15-minute window, stored in Postgres: 5 failures for the same email (it exists or not) block the sixth even with the right password (`429 CUENTA_BLOQUEADA`); 20 failures from one IP give `429 DEMASIADOS_INTENTOS`. Both include `reintentar_en_segundos` and `Retry-After`. Rejected attempts do not extend the lock; a successful login resets the account count.

### Renew and close: `POST /api/v1/sesiones/renovacion`, `DELETE /api/v1/sesiones/actual`

- Renewal requires `X-Solicitado-Con: front` (`403 ORIGEN_NO_PERMITIDO` without it) and the cookie. It returns a new token and rotates the cookie. A missing, expired or already used cookie gives `401 TOKEN_INVALIDO` and clears the cookie. Supabase Auth tolerates two renewals with the same cookie within 10 s (several tabs).
- Close needs the Bearer token. It revokes the session in Supabase (`scope=local`), clears the cookie and returns `204`; the cookie no longer renews.

### Email verification and recovery

6-digit codes, sent by Supabase Auth in Spanish, valid 15 minutes, single use. None of these routes returns tokens.

| Route | Result |
|---|---|
| `POST /api/v1/verificaciones-correo` | `200 { "mensaje": "Correo verificado. Ya puedes iniciar sesión." }`. Wrong, expired, used code or unknown email: `400 CODIGO_INVALIDO`, always the same body |
| `POST /api/v1/verificaciones-correo/reenvio` | `202 { "mensaje": "Si el correo está registrado y sin verificar, te enviamos un código." }`, the same whether the email exists or not |
| `POST /api/v1/recuperaciones` | `202 { "mensaje": "Si el correo está registrado, te enviamos un código." }`, the same whether the email exists or not |
| `POST /api/v1/recuperaciones/restablecimiento` | `200 { "mensaje": "Contraseña actualizada. Inicia sesión con la nueva." }`. The strict password policy runs before spending the code (`422 CONTRASENA_INSEGURA`, also `distinta_de_la_actual`); on success every session is revoked (`/logout?scope=global`) and Supabase sends the password-change notice |

`reenvio` and `recuperaciones` record the request, answer, and only then call Supabase Auth in the background (`BackgroundService`), so the response time does not reveal whether the email exists.

Limits (table `autenticacion.eventos_codigo`, counted by the email text even if the account does not exist; rejected requests are not recorded):

| Limit | Window | Response |
|---|---|---|
| 3 code requests per email and purpose | 1 hour | `429 DEMASIADOS_INTENTOS` + `Retry-After` |
| 10 code requests per IP | 1 hour | `429 DEMASIADOS_INTENTOS` + `Retry-After` |
| 5 wrong codes per email and purpose | 15 minutes | `429 CODIGO_BLOQUEADO` + `Retry-After` (also rejects the right code) |
| 20 wrong codes per IP | 15 minutes | `429 DEMASIADOS_INTENTOS` + `Retry-After` |

### Error format

Every error, from any layer, has this shape:

```json
{ "error": { "codigo": "CONTRASENA_INSEGURA", "mensaje": "La contraseña no cumple los requisitos.",
             "detalles": [ { "campo": "contrasena", "regla": "minimo_12_caracteres", "mensaje": "Debe tener al menos 12 caracteres." } ] } }
```

`detalles` only appears in `VALIDACION_FALLIDA`, `CONTRASENA_INSEGURA` and (in development) `SOLICITUD_INVALIDA`; `reintentar_en_segundos` only in the `429` lockouts and limits.

| Code | HTTP | When |
|---|---|---|
| `JSON_INVALIDO` | 400 | the body is not JSON |
| `VALIDACION_FALLIDA` | 422 | missing, extra, wrongly typed or malformed fields |
| `CONTRASENA_INSEGURA` | 422 | the password breaks the policy |
| `CREDENCIALES_INVALIDAS` | 401 | unknown email or wrong password |
| `TOKEN_INVALIDO` | 401 | access or refresh token missing, invalid, expired or revoked |
| `ORIGEN_NO_PERMITIDO` | 403 | `Origin` other than `ORIGEN_FRONT`, or `X-Solicitado-Con` missing on renewal |
| `CORREO_NO_VERIFICADO` | 403 | correct password on an unverified account |
| `SIN_PERMISO` | 403 REST, 200 GraphQL field error | the user lacks the role the field requires, is not the owner or team of the course, or the webhook secret is missing or wrong |
| `NO_ENCONTRADO` | 404 | unknown route |
| `METODO_NO_PERMITIDO` | 405 | method the route does not accept (with `Allow`) |
| `TIPO_CONTENIDO_NO_SOPORTADO` | 415 | `Content-Type` is not `application/json` |
| `CUERPO_DEMASIADO_GRANDE` | 413 | body over 10 KB |
| `CODIGO_INVALIDO` | 400 | wrong, expired or used code, or unknown email |
| `CODIGO_BLOQUEADO` | 429 | 5 wrong codes for the email in 15 min |
| `CUENTA_BLOQUEADA` | 429 | 5 login failures for the email in 15 min |
| `DEMASIADOS_INTENTOS` | 429 | 20 failures of the IP, code request or wrong-code limits, or a Supabase Auth limit |
| `DEMASIADAS_SOLICITUDES` | 429 | more than 120 requests per minute from one IP, with `Retry-After` (new) |
| `CONSULTA_NO_PERMITIDA` | 400 | in production, a GraphQL operation that is not in the persisted manifest (new) |
| `CONSULTA_DEMASIADO_COMPLEJA` | 400 | GraphQL depth over 8 or cost over 1000 (new) |
| `SOLICITUD_INVALIDA` | 400 | GraphQL syntax or validation error (new) |
| `ERROR_INTERNO` | 500 | any unexpected failure, without internal details |

School codes (SPEC 07 and 08, unchanged by the migration; in GraphQL they travel in `errors[].extensions.codigo`, with `detalles` when they have them):

| Code | HTTP (REST) | When |
|---|---|---|
| `CURSO_EN_REVISION` | 409 | editing, syllabus, cover or video change on a course `en_revision` |
| `CURSO_INCOMPLETO` | 422 | `enviar_revision` with missing data; `detalles[].regla` is one of `falta_subtitulo`, `falta_descripcion`, `falta_nivel`, `falta_categoria`, `falta_portada`, `falta_secciones`, `seccion_vacia`, `falta_video` (`campo` is `curso`) |
| `ESTADO_INVALIDO` | 409 | wrong state for the action (review, retry video, inviting yourself, removing your own admin role) |
| `CATEGORIA_DUPLICADA`, `CATEGORIA_EN_USO` | 409 | category name already exists / category has courses |
| `USUARIO_NO_REGISTRADO` | 404 | no account for that email, or the account is not verified yet |
| `YA_ES_MIEMBRO`, `INVITACION_DUPLICADA` | 409 | the person is already on the team / a pending invitation exists |
| `PORTADA_INVALIDA` | 422 | cover type, size or path rejected |
| `VIDEO_INVALIDO` | 422 | video type or size rejected, or the uploaded file does not match |
| `VIDEO_EN_PROCESO` | 409 | the lesson already has a video uploading or processing |
| `SERVICIO_NO_DISPONIBLE` | 503 | the transcoder did not accept the job (the video stays in `error`) |

`NO_ENCONTRADO` (404, with a specific message such as "El curso no existe.") is also what a resource that does not exist, or a draft course in the public catalog, answers. **GraphQL answers `200` with `data: null` and `errors[0].extensions.codigo`** for these domain errors (the HTTP status in the table is the REST one); only failures before execution (limits, allow-list, complexity) use their own status.

## Edges of the school (REST)

Three routes, all JSON, with the uniform error format. Only the first two need a session; the third is for the transcoder.

| Route | Who | Input -> output |
|---|---|---|
| `POST /api/v1/portadas/firmas` | `@Roles('instructor')`, owner of the course, course not `en_revision` | `{ curso_id, tipo_contenido, tamano_bytes }` -> `201 { url_subida, ruta }` |
| `POST /api/v1/videos/firmas` | `@Roles('instructor', 'equipo_apoyo')`, owner or team, course not `en_revision` | `{ clase_id, nombre_archivo, tipo_contenido, tamano_bytes }` -> `201 { video_id, url_subida, ruta }` |
| `POST /api/v1/interno/video-procesado` | the transcoder (no JWT) | `{ video_id, resultado: 'listo' \| 'error', duracion_segundos?, mensaje? }` -> `200 { aplicado }` |

**Cover signature.** Order of checks: role (`401 TOKEN_INVALIDO` / `403 SIN_PERMISO`), validation (`curso_id` 1..9007199254740, `tipo_contenido` 1..100, `tamano_bytes` 1..1000000000, no extra fields: `422 VALIDACION_FALLIDA`), `CourseAccessPolicy` (`404 NO_ENCONTRADO`, `403 SIN_PERMISO`, `409 CURSO_EN_REVISION`), then the cover rules: JPG, PNG or WebP of at most 2 097 152 bytes, else `422 PORTADA_INVALIDA`. `url_subida` is `/almacen` + the path Storage signs (`/object/upload/sign/portadas/<ruta>?token=...`); the browser `PUT`s the file there (the Astro proxy takes `/almacen/x` to Kong `/storage/v1/x`) and then calls `confirmar_portada`. `ruta` is `cursos/<curso_id>/portada-<32 hex>.<jpg|png|webp>`.

**Video signature.** Same order, then `video/mp4`, `video/quicktime` or `video/webm` of 1..1 073 741 824 bytes (`422 VIDEO_INVALIDO`) and `409 VIDEO_EN_PROCESO` if the lesson already has a video `esperando_archivo`, `en_cola` or `procesando`. It creates the `esperando_archivo` row (`ruta_base` with the real ids) and its AES-128 key (`crypto.randomBytes(16)`, stored only in `claves_video`). `url_subida` is `/almacen/object/upload/sign/videos/<ruta>?token=...`; the browser `PUT`s the file with the same `Content-Type` and then calls `confirmar_subida_video`.

**Internal webhook.** Requires the header `X-Secreto-Transcodificador` equal to `SECRETO_TRANSCODIFICADOR` (constant-time comparison); missing or wrong -> `403 SIN_PERMISO`. The transcoder port is not published; port 3000 is the only one of the API, so the secret is what protects the route. `listo` makes the video current and deletes the previous one in a single SQL statement; `error` stores the message. It only applies to videos `en_cola` or `procesando`, so the transcoder's retries (up to 5) and deleted videos answer `200 { aplicado: false }`.

## GraphQL contract (`POST /api/graphql`)

Mercurius, code-first, no version in the path (GraphQL evolves by adding fields and deprecating). Fields are Spanish `snake_case`, like the REST bodies. Ids are the `EnteroGrande` scalar (an integer up to 2^53 - 1, validated to 1..9007199254740); category ids are `Int`; user ids are `ID` (uuid). The schema is written to `api/graphql/schema.graphql` on startup in development and is versioned. **33 operations: 12 queries and 21 mutations.**

Persisted request (what the frontend sends; the hash is in `persisted-queries.json`):

```http
POST /api/graphql
Authorization: Bearer <token_acceso>
Content-Type: application/json

{ "operationName": "mis_roles", "variables": {},
  "extensions": { "persistedQuery": { "version": 1, "sha256Hash": "<hex>" } } }
```

```json
200  { "data": { "mis_roles": { "roles": ["instructor"], "equipos": [] } } }
```

Development only, the full query is also accepted: `{ "query": "query yo { yo { correo id nombre } }" }`. `protections.ts` accepts three forms and reduces them to Mercurius' native one: `{ "documentId": "<hash>" }`, `{ "extensions": { "persistedQuery": { "version": 1, "sha256Hash": "<hash>" } } }` and `{ "query": "<hash>", "persisted": true }`, with or without the `sha256:` prefix. A valid hash is never mixed with text: if the request carries `query` without `persisted: true`, it counts as a full query.

Error shapes:

- The request fails before running (limit, method, type, size, allow-list, syntax, validation, complexity): its own HTTP status and `{ "error": { codigo, mensaje, detalles? }, "errors": [{ message, extensions: { codigo } }] }`. The `errors` array repeats the error in GraphQL form so the client does not treat it as a network failure.
- A field fails (token, role, policy, resolver exception): `200 { data: null, errors: [{ message, locations, path, extensions: { codigo, detalles? } }] }`, for example `extensions.codigo = "TOKEN_INVALIDO"`. An error without its own code goes out as `ERROR_INTERNO` without details.

### Permissions

1. **Authentication:** `GraphqlAuthGuard` verifies the access JWT locally (HS256 with `JWT_SECRET`, `aud = authenticated`, `iss = API_EXTERNAL_URL`, not expired). Missing, expired, wrong key, `aud` or `iss`: `TOKEN_INVALIDO`. Only `categorias`, `cursos` and `curso` have no guard (no token needed, same rate limit).
2. **Role (`@Roles('x', 'y')`):** includes the authentication and **queries `escuela.roles_usuario` in the database** (the token's `role` claim is just `authenticated`); the user needs any of the listed roles, else `SIN_PERMISO`. Roles: `administrador`, `instructor`, `equipo_apoyo` (the student is implicit). `@Roles` also works on REST routes (the guards read the request from either context). A role change takes effect on the next request.
3. **Ownership (`CourseAccessPolicy`, `modules/courses/policies/course-access.policy.ts`):** the only place that decides who may touch a course. `authorize(userId, { type: course|section|lesson|video, id }, { mode: owner|owner_or_team, editable })` answers, in this order, `NO_ENCONTRADO` ("El curso no existe.", 404), `SIN_PERMISO` (403) and, when `editable`, `CURSO_EN_REVISION` (409). `owner` is the instructor who owns the course; `owner_or_team` also lets in the members of that instructor's support team (they edit syllabus and videos, but not course data, cover, review or the team). Resolvers call role first, then validation, then the policy. Positions are always `1..n`: every reordering runs in a transaction that locks the course row first (the position constraints are `DEFERRABLE INITIALLY DEFERRED`).

### GraphQL protections

| Protection | Behaviour |
|---|---|
| Local JWT guard | `@Authenticated()` on a field (or `@Roles(...)`, which includes it), see Permissions |
| Depth and cost | Maximum depth 8 and cost 1000 (1 per requested field, aliases and fragments counted each time they are used) -> `400 CONSULTA_DEMASIADO_COMPLEJA`. Own rule (Mercurius has no cost): an iterative pass before validation, see below. Development introspection (operations made only of `__*`) is not measured; in production it is closed |
| Persisted queries | `NODE_ENV=production`: only the hashes of `graphql/persisted-queries.json`; full text, unknown or malformed hash -> `400 CONSULTA_NO_PERMITIDA`. Development: full text and hashes are accepted |
| Introspection and GraphiQL | Production: introspection closed (`__schema` fails) and `GET /graphiql` -> `404`. Development: both active (with a relaxed CSP only on `/graphiql`) |
| Method and type | `POST` with `application/json` only: `405` with `Allow: POST`, `415` if not JSON or no body, `413` above 10 KB, `400 JSON_INVALIDO`, no batching (an array gives `400`), no cookies (no CSRF surface: the token goes in `Authorization`) |
| Rate limit | 120 requests per minute and per IP, counted per HTTP request (not per field) -> `429 DEMASIADAS_SOLICITUDES` with `Retry-After`. GraphQL has its own bucket (key `graphql-<ip>`); in REST `@nestjs/throttler` counts per route, so the 120 are per IP and route, not a global shared total. The public catalog queries have the same limit |
| Validation errors | `400 SOLICITUD_INVALIDA`; no "Did you mean ..." suggestions and, in production, no `detalles` |

### Cost and depth: list multipliers (`LIST_SIZES`)

`src/modules/graphql/query-complexity.ts` measures depth (nested fields; fragments add no level) and cost. Outside lists every field costs 1. A field whose name is in `LIST_SIZES` is a list and costs `1 + size x (1 + cost of its nested lists)`; inside a list each element costs 1 (its scalar fields and one-to-one objects are included) and only nested lists multiply again. Current sizes:

| Field | Size | Reason |
|---|---|---|
| `categorias` | 50 | |
| `cursos` | 12 | one catalog page |
| `mis_cursos` | 50 | |
| `cursos_en_revision` | 1 | the admin asks for each pending course with its full syllabus; with 50 x (20 x 30) not even one would fit under 1000, so it counts as one course with a full tree (the real queue is short) |
| `secciones` | 20 | |
| `clases` | 30 | |

A full `curso_edicion` (`secciones[].clases[]` with video fields) costs 656, so one fits and two in the same query do not. The multiplier is a fixed estimate by field name (the rule does not know the schema), not the real size of the response: a course with more sections than `LIST_SIZES.secciones` is still returned whole. **To adjust:** edit `LIST_SIZES` (name of the list field as it appears in the contract), then run `npm test`: `query-complexity.spec.ts` measures the heavy real queries of the frontend (a full `curso_edicion` fits once and not twice, a catalog page of 12, the review queue) and fails if one of them no longer fits under `MAX_COST` (1000). Add a case there when a new heavy query appears. If a new list field is added to the schema without an entry, it is counted as a single field.

### Persisted queries: regenerate and verify the manifest

The manifest `api/graphql/persisted-queries.json` is `{ "sha256:<hex of the printed document>": "<document>" }` (33 entries) and is versioned in git. The frontend codegen (GraphQL Code Generator, client preset with `persistedDocuments`) writes it from the operations in `frontend/src/features/*/api/`. Run it whenever an operation of the frontend changes:

```bash
cd frontend && npm run codegen        # types in src/shared/graphql/generated/ and api/graphql/persisted-queries.json
cd api && npm run graphql:verificar   # every key is the sha256 of its query and it parses against the schema
docker compose up -d --build api      # production only accepts the hashes baked into the image
```

`npm run build` and `npm run dev` of the frontend run the codegen first, so the manifest cannot fall behind. **In production the API only accepts hashes of the manifest**: a full query text, an unknown hash or a malformed one gets `400 CONSULTA_NO_PERMITIDA`, and there is no introspection.

## Rate limit

120 requests per minute and per IP (in memory, one instance; no Redis). REST counts per route with `@nestjs/throttler`; GraphQL has its own bucket. Over it: `429 DEMASIADAS_SOLICITUDES` with `Retry-After`. The login, account and code lockouts of SPEC 04 and 05 live in Postgres and are independent. Restart the `api` container to clear the counters.

## Storage, covers and videos

`StorageService` (`SERVICE_ROLE_KEY`, `URL_STORAGE`) is the only door to Supabase Storage. Any network failure, timeout or unexpected answer is `500 ERROR_INTERNO` without details; the key is never logged. Buckets: `portadas` (public, 2 MB, JPEG/PNG/WebP: `create-covers-bucket.sh`) and `videos` (private, 1 GiB: `create-videos-bucket.sh`).

- **Covers:** signature -> `PUT` to the signed URL -> `confirmar_portada`. The cover is readable without a session at `/almacen/object/public/portadas/<ruta>`.
- **Videos:** signature -> `PUT` -> `confirmar_subida_video` -> the transcoder converts the MP4 to AES-128 encrypted HLS under `cursos/<curso>/secciones/<seccion>/clases/<clase>/<video>/hls/` (`lista.m3u8` with `METHOD=AES-128` plus segments), deletes the original and calls the webhook. The key lives only in `escuela.claves_video` (16 random bytes, never in a response).

### The transcoder and its callback

The `transcodificador` service (`./transcodificador`, ffmpeg, internal network only, `mem_limit: 2g`, no published port) receives jobs from the API (`POST http://transcodificador:8090/trabajos`, header `X-Secreto-Transcodificador`, answer `202`), downloads the original from Storage with the service key, transcodes it and reports the result with `POST` to its `URL_CALLBACK`, which is `http://api:3000/api/v1/interno/video-procesado` (the internal webhook above, same secret in the header). It limits a lesson to 30 minutes ("dura más de 30 minutos") and retries the callback up to 5 times. A job asked while the transcoder is down leaves the video in `error` with `503 SERVICIO_NO_DISPONIBLE`; `reintentar_video` re-queues it. The queue is in memory: restarting the transcoder loses jobs in process (they end as `error` through the 45-minute rule of `estado_video`).

## Email

- **Auth templates:** `src/modules/mail-templates/` serves the `*.html` files of `api/templates/` from memory at `GET /plantillas-correo/:nombre` (the name must match `^[a-z0-9_]+\.html$` and is looked up in a map loaded at startup: no listing, no path reading). Supabase Auth downloads them from `http://api:3000/plantillas-correo/...` (`GOTRUE_MAILER_TEMPLATES_*` in `supabase/docker-compose.yml`); `auth` depends on `api` (`service_started`). If `api` is down when Supabase sends, the email goes out with the default English template. Templates: `verificacion.html`, `recuperacion.html` and `cambio_contrasena.html`; they contain no secrets.
- **Team invitation:** `MailService` over `nodemailer`. `From: Medical School <no-responder@escuela.local>`, subject `<nombre del instructor> te invitó a su equipo de apoyo`, HTML from `api/templates/team-invitation.html` (Spanish, no links; values are HTML-escaped and the deadline is formatted `es-MX` in Mexico City time). It goes over SMTP (`SMTP_HOST`/`SMTP_PORT`, `mailpit:1025`, no TLS). The name has a hyphen, so `mail-templates` never serves it over HTTP (covered by a test).
- In local, mail goes to Mailpit (`http://127.0.0.1:8025`). To use a real SMTP, change `SMTP_*` in `.env`, recreate `auth` and `api`, and remove `mailpit`.

`/escuela/*` answers `404 NO_ENCONTRADO`: the school lives under `/api/graphql` and the REST edges. The transcoder reports to the API (`/api/v1/interno/video-procesado`).

## Known limits

- **A valid access token lives up to 15 minutes after closing the session.** The JWT is verified locally (fast, no call to Supabase Auth), so it is not checked against the session. The refresh cookie is invalidated immediately.
- **Rate limit in memory:** it is lost when the container restarts and does not work across several instances. REST counts per route, GraphQL has its own bucket.
- **Mailpit is for development only:** anyone reaching `127.0.0.1:8025` reads the codes, and mail is lost on restart. In production use a real SMTP.
- **6-digit codes:** 1,000,000 combinations; mitigated by 5 wrong codes per email and 20 per IP every 15 minutes and the 15-minute expiry.
- **Background mail failures go unnoticed:** `reenvio` and `recuperaciones` answer `202` before sending; if the SMTP is down the email never arrives and it is only seen in the `auth` and `api` logs. An invitation email that fails is reported as `correo_enviado: false`.
- **Supabase Auth and Storage are still reachable** through Kong (`/auth/v1/*`, `/storage/v1/*` on port 8000, guarded only by the `anon` key): whoever uses Auth skips this API's password policy, limits and code verification.
- **No TLS:** the cookie has no `Secure` attribute and there is no HSTS; they come with an HTTPS domain.
- **Client IP in local:** on Docker Desktop local clients may share the gateway IP unless `X-Forwarded-For` comes from the Astro proxy (`xfwd`), so IP-based limits can act on everyone together.
- **Cookie reuse:** Supabase Auth tolerates reuse within 10 s and returns the same successor while nobody has used it; it does not revoke the rest of the session on detecting reuse.
- **The list multipliers are estimates** by field name, not the real size (see `LIST_SIZES`); a response is never truncated by them.
- **Transcoder:** in-memory queue (a restart loses jobs in process), one quality, 30-minute limit per lesson, and no cleanup of abandoned uploads (a signed video that is never confirmed stays as `esperando_archivo` with its object in Storage).
- **Webhook protected only by the shared secret:** port 3000 is the single port, so the route is reachable from the host; without `X-Secreto-Transcodificador` it answers `403`.
- **Video playback is not served yet** (protected playback, deliverable key and signed read URLs are SPEC 12); the key stays in the database.
- **Courses cannot be deleted** (only retired back to draft) and there are no GraphQL subscriptions, DataLoader or server-side response cache.
